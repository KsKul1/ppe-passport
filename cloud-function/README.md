# API «Паспорт ППЭ» (черновик развёртывания)

Функция рассчитана на Node.js 22+, бессерверную YDB и папку приложения на Яндекс Диске. Пока её URL не задан в сайте, текущая публикация на GitHub Pages продолжает работать только с данными браузера.

## Настройка базы

В консоли YDB выполните `schema.sql` в редакторе запросов **один раз**. Таблица `records` хранит отдельные документы паспортов и замечаний по коду ППЭ и счётчик версии для проверки конкурирующих изменений.

## Настройка функции

1. В каталоге с YDB создайте Cloud Function `ppe-passport-api`. Выберите среду **Node.js 22** (или новее), точку входа `index.handler`, память от 512 МБ, таймаут от 30 секунд. Назначьте функции подготовленный сервисный аккаунт с доступом `ydb.editor` к базе.
2. Загрузите **только** `index.js` и `package.json` из этой папки как файлы функции. Не публикуйте `hash-password.mjs` и секреты. Зависимости из `package.json` должны устанавливаться при сборке версии.
3. В настройках версии задайте переменные окружения:
   - `YDB_CONNECTION_STRING`: `grpcs://ydb.serverless.yandexcloud.net:2135/?database=/ru-central1/b1grkvvk0o7fpvgilg89/etn97e6lt47dgk1jr5i5`
   - `SITE_ORIGIN`: `https://kskul1.github.io`
   - `YANDEX_DISK_TOKEN`: OAuth-токен с доступом `cloud_api:disk.app_folder`, полученный **от аккаунта владельца Диска**.
   - `SESSION_SECRET`: случайная строка минимум 32 символа; не совпадающая с другими паролями.
   - `ADMIN_LOGIN`: новый логин администратора (например, `ppe.admin`).
   - `ADMIN_PASSWORD_HASH`: хеш нового пароля. Сгенерируйте его локально командой `node cloud-function/hash-password.mjs` (не используйте опубликованный демопароль `lnr2026`). Хеш можно скопировать из вывода, сам пароль сохраняйте отдельно.
   - `ADMIN_NAME`: отображаемое имя администратора.
4. Сделайте функцию доступной для вызова **без авторизации Яндекс Cloud**: сайт самостоятельно получает пользовательский токен через `/login`; остальные методы проверяют его на сервере. Секреты в коде сайта и GitHub не размещайте. Укажите CORS-источник именно `https://kskul1.github.io`.
5. Проверьте `GET <URL_ФУНКЦИИ>/health` — ответ должен быть `{"ok":true}`. Затем войдите в API командой HTTP POST `<URL_ФУНКЦИИ>/login` с JSON `{"login":"<ваш логин>","password":"<ваш пароль>"}`: ожидается `token` и `account`. Не пересылайте пароль или токен в переписке.

Рекомендуется использовать переменные окружения через секреты Яндекс Cloud, если эта возможность доступна при создании версии функции. Обычные переменные функции видны тем, у кого есть права на просмотр её конфигурации.

## API

Все методы, кроме `/health` и `/login`, требуют заголовка `Authorization: Bearer <token>`. `GET /snapshot` отдаёт только доступные вошедшему пользователю записи. `POST /document` принимает `{kind,key,data,revision}` и при несовпадении версии возвращает HTTP 409. `POST /account` создаёт нового пользователя с паролем (доступно только администратору); `GET /accounts` отдаёт список без хешей. `/file/upload` и `/file/download` используют папку `app:/ppe-passport` на Диске и передают данные через base64 (файлы не более 5 МБ).

**Не отправляйте коллегам ссылку на функцию вместо ссылки на сайт.** После проверки функции сообщите только её публичный URL: тогда можно подключить сайт к API, выполнить перенос уже заполненных данных из браузера и проверить синхронизацию. До этого удалять данные браузера нельзя.
